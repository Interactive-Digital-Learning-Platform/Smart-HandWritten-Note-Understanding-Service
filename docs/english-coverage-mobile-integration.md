# Automatic English coverage suggestions in the mobile app

2026-10-07. The user chose automatic model checks on uploaded notes and display
in the mobile application. This closes the gap left by the earlier reviewer-only
integration and standalone web demo.

## Implemented flow

Normal upload-and-process requests already call `processNote` and the pipeline.
The pipeline now runs `english_coverage_check` after concept matching and before
coverage calculation. Its output is saved as `Note.analysis.englishCoverageCheck`
alongside the other analysis fields and is returned by the existing note API.
The normal mobile note detail screen renders `EnglishCoverageCard` from that
field. No separate reviewer login or research opt-in is required to see the
model check on the student's own note.

The card displays a suggestion for each supported concept and an expandable
checklist with quoted evidence and flagged concerns. Labels are **Suggested
complete**, **Partial coverage**, **Not found in this text**, or **Needs review**
when the complete suggestion is withheld. Scores are not presented as correctness
probabilities. The saved prediction and card both require review. These are
coverage suggestions rather than a certified assessment of student understanding.

The check runs only for confidently detected English text, usable OCR, a
confidently matched lesson, and concepts supported by the frozen model. It skips
incomplete/low-quality OCR, uncertain lesson scope and unsupported concepts.
Runtime failure records an unavailable check and a quality warning; the rest
of the note pipeline can finish.

The model's canonical reproduction ID `sci-g10-col-001` is explicitly mapped to
the current reviewed registry ID `sci-g10-cho-007` (Reproduction: Sexual and
Asexual). The saved suggestion retains both source and model IDs. No fuzzy
name matching is used. The current registry represents eight of the ten model
targets after this mapping. Ohm's law and reaction classification require
matching reviewed registry entries before normal uploads can select them;
the frozen model and manual reviewer catalog still support all ten.

Pipeline metadata is now version 2.1.0. The learned model and its inference
source remain frozen at V3 and the original SHA-256. Existing note scores and
learning-profile calculations continue to use their existing analysis contract;
the new card identifies the model's separate suggestions.

## OCR provider repair (2026-10-07)

A real three-page upload failed before coverage inference because the hard-coded
`qwen/qwen3.6-27b` OCR model returned HTTP 404 for every page. The provider's live
model listing and vision documentation identify `qwen/qwen3.8-27b` as available.
OCR now defaults to that model, with an independent `GROQ_OCR_MODEL` override;
the unavailable model was also removed from text-generation fallbacks.
The local note server was rebuilt and restarted. All 48 backend tests passed,
including a regression check that the configured image model reaches the OCR
request. A newly generated synthetic text image was successfully transcribed
through the real provider. This confirms the connection and request format,
not handwriting accuracy. Automatic approval review initially blocked retrying
the saved student upload until explicit permission to resend its images to Groq.
After the user approved, the existing three-page upload was retried without
re-uploading: all three pages produced OCR text, the lesson matched Chemical
Basis of Life, analysis was saved, and one revision summary was generated.

Provider reference: https://console.groq.com/docs/vision

It also exposed a Windows Python bridge encoding issue: UTF-8 symbols were decoded
with the system code page, shifting evidence offsets. Python now receives explicit
UTF-8 I/O settings. The service converts Python code-point offsets to JavaScript
UTF-16 offsets and rejects evidence quotes that do not match the submitted text.
The build and all 11 model/HTTP/pipeline checks passed, including Unicode/emoji
offset regression coverage. The reviewed note's `analysis.englishCoverageCheck`
was refreshed locally from unchanged OCR text; all evidence offsets now match.
The frozen model, note text, other analysis fields, and human labels were preserved.
Review artifacts are in `tmp/note-review-6ac5f2c4ea7b94f750d7db9e.json` and its
adjacent corrected transcription file in the parent workspace.

## Commands

From the service repository:

```powershell
npm run build
npm run test:coverage-pipeline
npm run test:coverage
npm run demo:coverage-mobile
npm run verify:coverage-note-flow
npm start
```

`verify:coverage-note-flow` needs the local note service running, invokes the
existing processing providers on synthetic text, creates one marked fixture
and removes it afterward. It does not upload a real student image.

From `Mobile-Application`:

```powershell
npx tsc --noEmit
npm run test:coverage-schema
npx expo start --web --localhost --port 8082
```
